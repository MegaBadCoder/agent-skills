# `/learn` — скилл глубокого понимания кода для Claude Code

[English](README.en.md) | **Русский**

Сократический «учитель» внутри Claude Code или любого вашего агента. Его задача — не объяснить код, а **убедиться, что вы его поняли**: проблему, решение, архитектуру и последствия. Понимание проверяется демонстрацией (пересказ, квизы, упражнения), а не вашим «понятно». Прогресс сохраняется между сессиями в чеклистах `.learning/`.

Зачем это нужно: когда значительную часть кода пишет агент, легко оказаться владельцем системы, которую вы не понимаете. Этот скилл превращает каждую сессию (или любой существующий код) в учебный материал — и не отпускает, пока понимание не станет вашим.

---

## Установка

```bash
mkdir -p ~/.claude/skills/learn
cp SKILL.md ~/.claude/skills/learn/SKILL.md
```

- **Глобально** (`~/.claude/skills/learn/`) — доступен во всех проектах. Рекомендуется.
- **Локально** (`.claude/skills/learn/` в репозитории) — только для этого проекта; можно закоммитить и поделиться с командой.

Если папки `skills/` до этого не существовало — перезапустите Claude Code один раз. Дальнейшие правки `SKILL.md` подхватываются на лету, без перезапуска.

Хотите другое имя команды? Имя задаётся **папкой**, не файлом:

```bash
mv ~/.claude/skills/learn ~/.claude/skills/изучи   # → команда /изучи
```

## Быстрый старт

```bash
/learn session                 # разобрать то, что мы только что написали в этой сессии
/learn src/auth/               # глубокий разбор модуля
/learn -m src/processing/      # быстрая карта: функции, классы, связи
/learn -r                      # продолжить незаконченную тему
/learn -l                      # что я сейчас изучаю и где остановился
```

Скилл также срабатывает **автоматически**, без команды — на фразы вроде «объясни этот код», «как связаны эти классы», «проверь моё понимание», «разбери что мы сделали».

## Команда и флаги

```
/learn [-q|-m|-r|-l] [-t <тема/пути>] [-f <фокус>] [-n <число>]
```

| Флаг | Назначение |
|---|---|
| _(без флагов)_ | Полный цикл обучения (режим **teach**) |
| `-t <тема>` | Что изучаем: пути к файлам, имя модуля, ссылка на PR/коммит, слово `session` (текущая сессия) или слаг сохранённой темы. Можно и без `-t`, просто позиционно: `/learn src/auth/` |
| `-q` | Только **квиз** — проверка без обучения |
| `-m` | Только **карта** — структура функций/классов и их связей |
| `-r` | **Продолжить** тему с сохранённого чеклиста |
| `-l` | **Список** всех тем: статус, незакрытые пункты, дата последней сессии |
| `-f <фокус>` | Усилить акцент: `edge-cases`, `structure`, `why`. Фокус углубляет область, но не отменяет проверку остальных слоёв |
| `-n <число>` | Для квиза: количество вопросов (по умолчанию 5–8) |

Парсинг снисходительный: `--quiz` вместо `-q`, тема кириллицей, путь без `-t` — всё распознаётся по смыслу. Команда без аргументов запустит диалог выбора темы.

## Режимы

### Teach — полный цикл (по умолчанию)

Главный режим. Работает поэтапно, и **каждый этап закрывается только после того, как вы продемонстрировали понимание**.

1. **Выбор скоупа.** Сессия / файл‑модуль / PR‑дифф / онбординг в часть репозитория. Скилл сам читает код, `git log`/`git blame` и трассирует вызовы — он учит по реальному коду, а не по памяти разговора. Большая тема делится на несколько юнитов: глубина важнее охвата.

2. **Чеклист понимания** создаётся в `.learning/<тема>.md` — три слоя:
   - **Проблема**: что решаем, *почему* проблема вообще существовала (корень, а не симптом), какие были альтернативные ветки и почему их отвергли.
   - **Решение**: выбранный подход и его trade-off'ы, главный путь исполнения, граничные случаи, **инварианты** — что должно оставаться истинным, чтобы код был корректен.
   - **Контекст**: что эта работа меняет — для вызывающего кода, производительности, деплоя, других людей; где точки расширения и хрупкие места.

3. **Карта структуры** (для юнитов крупнее пары функций): сначала **вы** рисуете связи текстовыми стрелками (`upload → validate → parse → save`), потом скилл показывает корректную карту — Mermaid-диаграмма сохраняется в док, ASCII-версия выводится в терминал. На каждый узел — одна строка ответственности, включая то, что он *намеренно не делает*.

4. **Обучение по слоям.** Порядок жёсткий: сначала проблема, потом решение, потом контекст — нельзя разбирать «как работает код», не умея сформулировать, зачем он существует. Внутри каждого слоя:
   - сперва **вы пересказываете** своё текущее понимание — пробелы видны именно из пересказа;
   - скилл закрывает пробелы, по одной концепции за обмен;
   - на каждый «что» — минимум один «почему», на важные решения — «почему» второго порядка;
   - перед запуском кода или показом ответа — **предсказание**: «что ты ожидаешь увидеть?». Разрыв между ожиданием и реальностью — главный обучающий сигнал.

5. **Квизы** на границах этапов: открытые вопросы и multiple choice с правдоподобными дистракторами; ответ не раскрывается до отправки; позиция правильного варианта меняется.

6. **Активные упражнения** (минимум одно до финала): трассировка входа по коду, «сломай и почини», предсказание последствий изменения строки, реконструкция карты по памяти, teach-back (объясняете весь юнит «стажёру», скилл играет стажёра и задаёт наивно-каверзные вопросы), «требования изменились — что меняется?».

7. **Mastery Gate.** Сессия не завершается, пока: все чекбоксы трёх слоёв закрыты демонстрацией, выполнено хотя бы одно упражнение, и вы дали связный пересказ всего юнита своими словами. Если нужно прерваться — прогресс честно сохраняется, незакрытое остаётся незакрытым.

Калибровка уровня в любой момент: попросите **ELI5** (на пальцах), **ELI14** (старшеклассник) или **ELII** (explain like I'm an intern — как стажёру-разработчику).

### Quiz (`-q`) — проверка без обучения

```bash
/learn -q -t orbital -n 10
```

Берёт сохранённый чеклист темы: сначала пункты из «Mistakes & weak spots», затем интервальное повторение уже освоенного — с новыми формулировками, вопросы из лога не повторяются. Каждый промах объясняется по конкретным строкам кода. Результаты пишутся в док: лог квиза, снятые галочки с того, что вы явно забыли, новые слабые места. Квиз не сползает в обучение — закончил, предложил `-r` для пробелов. Без `-t` покажет список тем на выбор; если доков нет — спросит, по чему гонять, и сначала прочитает этот код.

Квиз запускаете только вы — посреди рабочей задачи Claude сам его не устроит.

### Map (`-m`) — карта кода

```bash
/learn -m src/processing/
```

Быстрый автономный артефакт без полного цикла: инвентарь ключевых функций/классов (5–15 узлов), связи (вызовы, владение, наследование/композиция, потоки данных), точки входа и границы, ответственность каждого узла. Отдельно помечаются **несущие** рёбра (изменение аукнется по графу) против случайных, и размытые границы ответственности. Mermaid — в `.learning/`, ASCII — в терминал. Если код писали вы — сначала вас попросят набросать карту самостоятельно.

### Resume (`-r`) — продолжить

```bash
/learn -r            # покажет незаконченные темы
/learn -r -t orbital # продолжить конкретную
```

Перед возобновлением скилл проверяет **актуальность**: смотрит `git log` с даты последней сессии. Если код с тех пор существенно поменялся — расскажет что именно и добавит новые пункты в чеклист, а не будет учить устаревшее. Затем 1–2 вопроса на повторение освоенного (промах — галочка честно снимается) и продолжение с первого незакрытого пункта.

### List (`-l`) — обзор прогресса

Все доки `.learning/*.md`: тема, статус, сколько пунктов не закрыто, дата последней сессии.

## Папка `.learning/`

Создаётся в корне репозитория. Один док на тему:

```markdown
# Understanding: <тема>
_Last session: <дата> · Status: in progress_

## 1. The Problem
- [x] Can state the problem in their own words
- [ ] Knows WHY the problem existed (root cause, not symptom)
...

## 2. The Solution
...карта кода (Mermaid), инварианты, граничные случаи...

## 3. The Broader Context
...

## Mistakes & weak spots (revisit next time)
- Путал владение SatelliteManager и сцены Three.js

## Quiz log
- 2026-06-10: Q про ground-track интерполяцию — мимо, см. weak spots
```

Это ваш персональный конспект: галочки ставятся только за продемонстрированное понимание, ошибки фиксируются дословно, диаграммы рендерятся в редакторе. Рекомендуется добавить `.learning/` в `.gitignore` (скилл сам предложит) — либо наоборот, коммитить, если хотите историю обучения в репо.

## Сценарии использования

**После рабочей сессии с агентом.** Claude написал вам фичу за час — прежде чем коммитить, `/learn session`. Через 20 минут вы понимаете каждое решение и сможете защитить этот код на ревью.

**Онбординг в чужой модуль.** `/learn -m src/legacy/billing/` для карты, затем `/learn -t src/legacy/billing/` для глубокого разбора по частям.

**Разбор PR коллеги.** `/learn -t PR#142 -f why` — упор на мотивацию решений.

**Подготовка к собеседованию по своему пет-проекту.** `/learn -q -t snake-dqn -n 10` раз в несколько дней: интервальное повторение по слабым местам само вытащит то, что вы плаваете объяснить.

**Длинная тема в несколько вечеров.** Первый вечер — `/learn`, прерваться можно где угодно; дальше каждый раз `/learn -r`.

## Поведение скилла: что он будет и не будет делать

Будет:
- требовать пересказ **до** объяснения и копать «почему» вглубь;
- показывать реальные строки кода и просить предсказать поведение до запуска;
- честно говорить «не уверен», если мотивацию решения нельзя проверить по коду/гиту;
- сохранять прогресс после каждого обмена.

Не будет:
- читать лекции на десять абзацев до того, как услышит вас;
- засчитывать «понятно» как доказательство;
- подсказывать ответ формулировкой вопроса или ставить правильный вариант всегда на одно место;
- перескакивать к «как работает код» мимо «зачем он существует»;
- заканчивать сессию с незакрытым чеклистом без вашего явного «стоп».

## Настройка под себя

Откройте `SKILL.md` и правьте — изменения применяются сразу, без перезапуска:

- **Мягче Mastery Gate**: ослабьте формулировки в разделе «Mastery Gate», если жёсткое «не отпущу» утомляет.
- **Размер квиза по умолчанию**: число в quiz mode.
- **Путь к конспектам**: замените `.learning/` на свой (например, общий `~/notes/learning/`).
- **Авто-срабатывание**: триггеры живут в `description` во frontmatter. Слишком навязчиво — удалите часть фраз; хотите только ручной вызов — добавьте `disable-model-invocation: true` (но тогда отвалятся и полезные автотриггеры вроде «объясни код»).

## Траблшутинг

| Симптом | Причина / решение |
|---|---|
| `/learn` не появляется в автокомплите | Файл должен лежать как `<папка>/SKILL.md`, не как `learn.md`. Если папка `skills/` создана только что — перезапустите сессию |
| Скилл не срабатывает на «объясни код» | Автотриггер вероятностный: простые запросы Claude может закрыть сам. Для гарантии — явный `/learn` |
| Конфликт имён | Если есть `.claude/commands/learn.md`, приоритет у скилла; уберите дубль во избежание путаницы |
| `-r` не находит тему | Проверьте, что вы в том же репозитории: `.learning/` живёт в корне проекта |
| Уроки слишком простые/сложные | Прямо в диалоге: «ELI5» / «ELII» / «давай жёстче» — скилл калибруется |
