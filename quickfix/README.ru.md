# `/quickfix`

Часть [agents](../) — скиллы для vibe coding в Cursor, Claude Code и Codex.

[English](README.md) · **Русский**

> Мелкие баги без церемоний: воспроизвести → гипотеза → минимальная правка → тест. Никогда не коммитит.

---

## Зачем

Однострочная правка, проверяемая против написанного плана, стоит больше внимания, чем сам баг. Хуже того, церемония заслоняет единственное, что важно: нашли причину или просто перестал показываться симптом.

`quickfix` оставляет от процесса ту часть, где сосредоточен риск: произнести гипотезу вслух, получить подтверждение, изменить одну вещь.

---

## Установка

```bash
npx skills add MegaBadCoder/agent-skills --skill quickfix -g -a claude-code -a cursor -a codex -y
```

Либо поставить весь набор плагином для Claude Code — см. [корневой README](../README.md#install).

## Протокол

1. **Воспроизвести** — симптом своими словами, `file:line`. Не воспроизводится → стоп.
2. **Гипотеза** — «думаю, причина в X, потому что Y». Дождаться подтверждения.
3. **Правка** — минимальная. Без уборки вокруг, без переименований, без новых абстракций.
4. **Тест** — самая узкая команда, покрывающая изменение; если теста на баг нет — добавить регрессионный.
5. **Отчёт** — что изменилось, по строке на файл. Коммитит пользователь, не агент.

## Условия остановки

Три места, где скилл отказывается продолжать:

- **Первая правка не помогла** → откатиться и диагностировать заново. Догадка поверх догадки уничтожает улики: уже не понять, какое из изменений дало то, что вы видите.
- **Причина оказалась в другом месте** → это больше не quickfix, нужен тот широкий взгляд, который пропустили.
- **Рука тянется к запасному варианту** — значение по умолчанию, проглоченное исключение, `try/except: pass` → это не починка, это сокрытие сбоя от следующего человека.

## Когда не подходит

Рефакторинг на несколько файлов, новая функциональность, изменение схемы или контракта. Там сначала нужен дизайн: неверная мелкая правка не в том месте хуже, чем медленная.
